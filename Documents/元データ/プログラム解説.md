235: function ListToCSV(list, header) {
236:     result = "";
237:     for(let i in header) {
238:         result = `${result}${header[i]},`;
239:     }
240:     result = result.slice(0, -1) + "\n";
241:     for(let i in list) {
242:         for(key in list[i]) {
243:             result = `${result}${list[i][key]},`;
244:         }
245:         result = result.slice(0, -1) + "\n";
246:     }
247:     return result;
248: };

測定データをダウンロードしたい需要はあるだろう。そんな時に便利なのがCSVという形式のファイルだ。CSVファイルには表データを保存することができ、Excelなどで開くことができる。 \
例えば、以下のような表データがあったとする。
| 電圧 | 電流 | 
| ---- | ---- | 
| 0.1  | 5    | 
| 0.2  | 6    | 
| 0.3  | 7    | 

これをCSVという形式で表すと、
```
電圧,電流
0.1,5
0.2,6
0.3,7
```
というようになる。つまり、カンマ(,)で列を区切り、改行で行を区切っているということだ。ちなみに列ラベル(今回なら電圧,電流)を区別する情報はCSVファイルに保存されない。読み込む際に手動で「1行目は列ラベルですよ」と伝える必要がある。 \
ではこれをjavascriptで生成してみる。まず、生成元の2次元リストが与えられる。そして、そのリストは列ラベル(プログラム内ではheaderと呼ばれている)と共に235行目から248行目にある`ListToCSV()`という関数に渡される。`ListToCSV()`はリストの中身を順番に取り出し、カンマと改行を付け加え、その結果を返している。 \
例えば、先程のCSVファイルを生成する場合は、
```
list = [[0.1, 5], [0.2, 6], [0.3, 7]]
header = ["電圧", "電流"]

csv = ListToCSV(list, header)
```
という具合になる。 \
あとは出来たファイルを自動でダウンロードさせれば良い。それを227行目から231行目で行っている。
> [!NOTE]
> **BOMについて** \
> 218行目と225行目に謎の処理がある。これは生成したCSVファイルにBOMと呼ばれる情報を追加している。これにより、このファイルのエンコード方法が指定されるため、外部ソフトで読み込む際の文字化けを防ぐことができる。

#### 平均化の処理について
そもそも、EIS測定における平均化には2種類ある。一つはハードウェア、つまりIMPACT側で行う平均化だ。もう一つはクライアント側で行う平均化だ。前者は各測定点において複数回測定を行い、平均化する方法。後者は測定完了後に同様の測定をもう一度行い、平均化する方法。ただ、言葉よりフローチャートを見たほうが分かりやすいと思う。 \
ハードウェア平均化では測定結果が加算された状態で渡されるので、799行目のように、最初に測定回数で割っている。クライアント平均化では860行目から869行目のように前回の測定データとの平均を都度計算している。 \

##### 読み取り処理
```javascript
01: class LineBreakTransformer {
02:     constructor() {
03:       this.chunks = "";
04:     }
05: 
06:     transform(chunk, controller) {
07:       this.chunks += chunk;
08:       const lines = this.chunks.split("\r\n");
09:       this.chunks = lines.pop();
10:       lines.forEach((line) => controller.enqueue(line));
11:     }
12: 
13:     flush(controller) {
14:       controller.enqueue(this.chunks);
15:     }
16: }
17: 
18: async function readTextSerial() {
19:     let textDecoder = new TextDecoderStream();
20:     port.readable.pipeTo(textDecoder.writable);
21:     while (port.readable) {
22:         const reader = textDecoder.readable
23:         .pipeThrough(new TransformStream(new LineBreakTransformer()))
24:         .getReader();
25:         try {
26:             while (true) {
27:                 const { value, done } = await reader.read();
28:                 if (done) {
29:                     console.log("Canceled");
30:                     break;
31:                 }
32:                 console.log(value);
33:             }
34:         } catch (error) {
35:             console.error(error);
36:         }finally {
37:             reader.releaseLock();
38:         }
39:     }
40: }
```
まず、前提としてシリアル通信で送られてくるデータは0と1からなるバイト列である。そのため、バイト列を文字列に変換する必要がある。 \
`バイト列(01010011....) -(変換)-> 文字列(Hello)`

また、得られるデータは「チャンク」と呼ばれる塊で分割されている。例えば、 \
`Hello World!\r\n` (\r\nは改行を表す)\
という文字列を受信したいという場合であっても、 \
`Hello`, ` World!\r\n` \
という2つの文字列に分割されてしまうかもしれないということである。ただ、それは不便であるから、できれば文字列は改行ごとに取得したい。そのため、受信した文字列は一時的に保存しておいて、`\r\n`が出てきたらそこで分割するという処理が必要である。 \
最終的な処理の流れは以下のようになる。 \
`バイト列(01010011....) -(変換)-> 文字列(Hello) -(処理)-> 一文の文字列(Hello World!\r\n)`

では実際の実装を見ていく。まず19行目で`TextDecoderStream`と呼ばれる物を取得している。これはバイト列を文字列に変換してくれるものだ。これを20行目でシリアル通信の読み取り部分と接続している。これにより、読み取ったバイト列は自動的に`TextDecoderStream`に渡されるようになる。これで以下のようなデータの流れが出来上がる。 \
`バイト列 -(変換)-> 文字列` \
23行目で出てくる`LineBreakTransformer`というのは1行目で定義しているように、文字列を一時的に保存して、改行ごとに分割してくれる処理である。これを`TextDecoderStream`に接続している。これで以下のようなデータの流れが出来上がる。 \
`バイト列 -(変換)-> 文字列 -(処理)-> 一文の文字列` \
あとは27行目のようにすれば一行ずつシリアル通信の読み取りを行うことができる。読み取った文に対して何か処理を行いたい場合は32行目の部分に入れれば良い。このプログラムでは単にデバッグコンソールに文を出力している。

### 校正について
例えば、正確な抵抗値の分かる抵抗などを測定機につなげ、以下のような測定値が得られた際に、(真の値に関しては抵抗値から算出する)
| 電圧値 | 測定値 | 真の値 |
| ---- | ---- | ---- |
| 0.1  | 3    | 1     |
| 0.2  | 5    | 2     |
| 0.3  | 7    | 3     |
| 0.4  | 9    | 4     |
| 0.5  | 11   | 5     |

測定値を真の値に近づける方法を考える。まず、一番実装が単純なのは測定値→真の値の変換表を作ることだ。
#### 測定値→真の値の対応表を作る方法
測定結果と抵抗値をもとに以下のような対応表が完成する。
| 測定値 | 真の値 |
| ---- | ---- |
| 3    | 1     |
| 5    | 2     |
| 7    | 3     |
| 9    | 4     |
| 11   | 5     |

そして、別の抵抗を測定したときに以下のような測定値が得られた場合、上記の表をもとに校正を行うことができる。
| 電圧値 | 測定値 | 校正後の値 |
| ---- | ---- | ---- |
| 0.2  | 3    | 1     |
| 0.4  | 5    | 2     |
| 0.6  | 7    | 3     |
| 0.8  | 9    | 4     |
| 1.0  | 11   | 5     |

この手法は単に測定値と真の値の関係を保存しておくだけで良く、実装が単純である。また、非線形(特定の値以降でズレが生じているなど)の誤差も校正することができる。 \
一方で、校正時に測定されてない値に関しては校正を適用することができない(例えば、上記の場合であれば、測定値が1であれば校正できない)。また、校正時の測定値にノイズが乗っている場合、その影響も受けてしまう。 \
とはいえそれなりに万能なので、まずはこの手法で実装してみて、限界を感じたら他の手法に挑戦するのが良いと思う。
#### 直線近似の傾きとy切片から求める方法
誤差の原因を考えると、大抵は抵抗値の誤差による傾きの変化とオフセットになる。例えば、「校正について」の最初に提示した表の場合であれば、真の値は`y=10x`(yは電流値、xは電圧値)で、測定値は`y=20x + 1`になる。つまり、傾きは真の値の2倍、かつ+1オフセットしている(y切片+1)ということになる。つまり、測定値から-1して、1/2すれば校正できるということになる。 \
例えば、別の抵抗を測定したときに以下のような測定値が得られた場合、
| 電圧値 | 測定値 | 校正後の値 |
| ---- | ---- | ---- |
| 0.2  | 3    | 1     |
| 0.4  | 5    | 2     |
| 0.6  | 7    | 3     |
| 0.8  | 9    | 4     |
| 1.0  | 11   | 5     |

このように校正できる。 \
より一般化すると、真の値が`y=ax + b`、測定値が`y = cx + d`であるとき、測定値に`b - d`を足した後、`a / c`倍すれば良いということである。 \
ただ、問題は`a, b, c, d`をどのように求めるかということだ。こんな時に便利なのが最小二乗法を用いた直線近似だ。これにより、最もフィットする直線の傾きやy切片を求められる(直線と各測定点との差の二乗を最小化する)。 \
求め方は以下を参考にしてほしい。 \
https://hooktail.sub.jp/computPhys/least-square/index.html \
この手法は校正時の測定値にノイズが乗っていてもあまり影響しない。その上、校正時に測定されていない値が測定されても、校正を適用することができる。 \

### オーバークロック
標準でシステムクロックはPicoが125MHz、Pico2が150MHzに設定されている。Arduinoよりは高いがESP32には及ばないくらいの値であるため、そこそこ高速だろう。 \
しかし、必要に応じてシステムクロックを手動で上げることも可能となっている。例えば、IMPACTの場合、Pico2を280MHzにオーバークロックして使用している。 \
当然、上げすぎると動作が不安定になることもある。ただ、手軽にすべての処理が高速になるため、諸刃の剣という感じである。 \
#### 具体的な手法
`set_sys_clock_pll(f_vco, post_div1, post_div2)`というプログラムでシステムクロックを変更することができる。プログラムのどこに配置しても動くのかは調べていないが、main関数の一番最初に配置するのが無難だろう。 \
注意点として、`f_vco`がそのままシステムクロックになるわけではない。システムクロックを`f_sys`とすると、 \
`f_sys = f_vco / ( post_div1 * post_div2 )` \
という式で求められる。ただ、f_vcoは750MHz~1600MHz、post_div1, post_div2は1~7の整数値という制限がある。例えば、システムクロックを125MHzにしたい場合は、 \
`f_vco = 1500 * MHz, post_div1 = 6, post_div2 = 2` \
になり、280MHzにしたい場合は、 \
`f_vco = 1120 * MHz, post_div1 = 2, post_div2 = 2` \
となる。 \
まぁ、それぞれのパラメータを決定するのはそれほど難しくないが、公式が、目的のシステムクロックを実現できる最適なパラメータを求められるpythonスクリプトを公開している。 \
https://github.com/raspberrypi/pico-sdk/blob/master/src/rp2_common/hardware_clocks/scripts/vcocalc.py \
それぞれのパラメータの制限に関してはrp2040データシートの229ページ、rp2350の576ページを参考にした。
### シリアル通信
#### 書き込み
`printf("Hello, world!\n");`で文字列を送信することができる。
#### 読み取り
```c
01: char command[128];
02: scanf("%s", command);
03: printf("Received command: %s\n", command);
```
これが基本的な読み取り方法である。これで、最初の空白までの内容を文字列として読み取ることができる。
#### サンプル
```c
01: #include "pico/stdlib.h"
02: #include <stdio.h>
03: 
04: int main() {
05:     stdio_init_all();
06:     char command[128];
07:     int argument;
08: 
09:     while (true) {
10:         scanf("%s", command);
11:         scanf("%d", &argument);
12:         printf("Received command: %s\n", command);
13:         printf("Received argument: %d\n", argument);
14:         sleep_ms(100);
15:     }
16: }
```
このプログラムを実行しつつ、例えば、`test 1234`と送信すると、
```
01: Received command: test
02: Received argument: 1234
```
という文字列が返ってくる。
### より高度なシリアル通信
#### 接続状態別LEDインジケータ
開発をしていると、「マイコンが完全に停止している」のか、「シリアル通信が死んでいる」のか、「受信しているが、処理はされていない」のか判断したい時がある(いずれも「PCから送信しているが応答は無い」という状態)。 \
そこで、ボードに搭載されているLEDに、接続待機時は1秒おきに点滅、接続後は受信したら一瞬点灯、という動作をさせることにする。ただ、このような動作は標準機能では再現できない。そこで、標準機能を使用せず、自前で用意することにする。
```c
01: #include <stdio.h>
02: #include "pico/stdlib.h"
03: 
04: // USBシリアル関連
05: #include "tusb.h"
06: #include "pico/stdio_usb.h"
07: 
08: static bool g_is_connected = false;
09: 
10: // タイマー関連
11: struct repeating_timer LED_timer;
12: 
13: #define LED_PIN 25
14: 
15: bool LED_timer_callback(struct repeating_timer *t) {
16:     if (gpio_get(LED_PIN) == 1) {
17:         gpio_put(LED_PIN, 0);
18:     } else {
19:         gpio_put(LED_PIN, 1);
20:     }
21:     return true;
22: }
23: 
24: int64_t LED_off_callback(alarm_id_t id, void *user_data) {
25:     gpio_put(LED_PIN, 0);
26:     return 0;
27: }
28: void tud_cdc_line_state_cb(uint8_t itf, bool dtr, bool rts) {
29:   (void) itf;
30:   (void) rts;
31: 
32:   g_is_connected = dtr; // DTRがONなら接続、OFFなら切断
33: 
34:   if (g_is_connected) {
35:     // 接続時は点滅を解除し、LEDを消灯
36:     cancel_repeating_timer(&LED_timer);
37:     gpio_put(LED_PIN, 0);
38:   } else {
39:     // 接続待機時はLEDを1秒間隔で点滅
40:     add_repeating_timer_ms(-1000, LED_timer_callback , NULL, &LED_timer);
41:     gpio_put(LED_PIN, 1);
42:   }
43: }
44: 
45: int main() {
46:     stdio_init_all();
47: 
48:     // USBシリアル初期化
49:     tusb_init();
50:     stdio_usb_init();
51: 
52:     gpio_init(LED_PIN);
53:     gpio_set_dir(LED_PIN, GPIO_OUT);
54:     gpio_put(LED_PIN, 0);
55: 
56:     char com_command[128];
57: 
58:     printf("system started\n");
59: 
60:     while (true) {
61:         tud_task();
62: 
63:         if (g_is_connected) {
64:             int result = scanf("%s", &com_command);
65: 
66:             if (result == 1) {
67:                 gpio_put(LED_PIN, 1);
68:                 add_alarm_in_ms(20, LED_off_callback, NULL, false);
69:                 printf("Received command: %s\n", com_command);
70:             }
71:         }
72:         else {
73:             sleep_ms(100);
74:         }
75:     }
76: }
```
15行目の関数は呼び出されるとLEDの明滅状態を反転させる。24行目の関数はLEDを消灯する。28行目の関数はどこからも呼び出されていない用に見えるが、実は内部で、usbの状態が変化したら呼び出されるようになっている。67行目と68行目が、シリアル通信を受信するとLEDを20ミリ秒だけ点灯させている。 \
`add_alarm_in_ms`は指定ミリ秒後に指定関数を実行してくれるものだ。よく見る実装方法だと、
```c
01: gpio_put(LED_PIN, 1);
02: sleep_ms(20);
03: LED_off_callback();
```
という方法が思いつくかもしれない。ただ、この場合、20ミリ秒間CPUを占有してしまうため、その後の処理にも20ミリ秒の遅延が発生してしまう。一方、タイマ割り込みであればCPUを占有しない。指定時間が来ていなければ先に以降のプログラムを実行してくれる。`add_repeating_timer_ms`もタイマ割り込みだ。 \
もし、「◯秒後や◯秒おきに特定の処理を行いたい」かつ「別の処理も並行して行いたい」という場合があればタイマ割り込みを使うことをおすすめする。
#### シリアル通信経由での書き込みモード化
Pico, Pico2はBOOTSELボタンを押しながらUSBを抜き差しすると書き込みモードになる(リセットボタンがある場合はBOOTSELボタンを押しながらリセットボタンを押せば良い)。ただ、プログラムを書き込みたいたびにUSBを抜き差しするのも面倒くさい。 \
そんなときはシリアル通信経由で書き込みモードに切り替える方法がある。やり方は簡単で、ボーレート(通信速度)を1200にした状態でPico. Pico2に接続するだけ。すると、瞬時に書き込みモードになる。 \
ただ、当然、シリアル通信が死んでいる場合はこの方法は使えない。
#### シリアル通信上のデバイス名を変更
通常、Pico, Pico2のシリアル通信上の名前は「Board CDC」に固定されている。ただ、変えたい時もあるかもしれない。そんなときは内部で使われているプログラムを強引に書き換えることで名前を書き換えることができる。 \
その前に、一応、変更予定のプログラムを見ておく。 \
https://github.com/raspberrypi/pico-sdk/blob/master/src/rp2_common/pico_stdio_usb/stdio_usb_descriptors.c \
名前に関係する部分だけを抜粋すると、 \
```c:stdio_usb_descriptors.c
136: static const char *const usbd_desc_str[] = {
137:     [USBD_STR_MANUF] = USBD_MANUFACTURER,
138:     [USBD_STR_PRODUCT] = USBD_PRODUCT,
139:     [USBD_STR_SERIAL] = usbd_serial_str,
140:     [USBD_STR_CDC] = "Board CDC",
141: #if PICO_STDIO_USB_ENABLE_RESET_VIA_VENDOR_INTERFACE
142:     [USBD_STR_RPI_RESET] = "Reset",
143: #endif
144: };
```
`USBD_STR_MANUF`などは変更できるようになっているが、`USBD_STR_CDC`だけがハードコードされている。 \
これを以下のように書き換え、 \
```c
140: static const char *const usbd_desc_str[] = {
141:     [USBD_STR_MANUF] = USBD_MANUFACTURER,
142:     [USBD_STR_PRODUCT] = USBD_PRODUCT,
143:     [USBD_STR_SERIAL] = usbd_serial_str,
144:     [USBD_STR_CDC] = USBD_CDC_PRODUCT_NAME,
145: #if PICO_STDIO_USB_ENABLE_RESET_VIA_VENDOR_INTERFACE
146:     [USBD_STR_RPI_RESET] = "Reset",
147: #endif
148: };
```
また、`USBD_CDC_PRODUCT_NAME`が指定されなかった時にデフォルト名を使用するようにする。 \
```c
56: #ifndef USBD_CDC_PRODUCT_NAME
57: #define USBD_CDC_PRODUCT_NAME "Board CDC"
58: #endif
```
その後、この書き換えたプログラムを使用するように指定すると、名前が自由に変更できるようになる。 \
ただ、このプログラムだけではなく、他の依存関係にあるプログラムもいくつか持ってこなければならない。 \
といったことを全てまとめたフォルダを以下に置いている。 \
https://github.com/oosan1/OriginalSMU_KKHS/tree/main/microcomputer/C_C%2B%2B/SMUcontrol/custom_src \
これをメインのプログラムと同じディレクトリに配置し、CMakeLists.txtに以下のような記述を書き足せば良い。`SMUcontrol`や`SMUcontrol.c`の部分は適宜書き換えてほしい。
```
42: add_executable(SMUcontrol 
43:     SMUcontrol.c
44:     custom_src/reset_interface.c
45:     custom_src/stdio_usb.c
46:     custom_src/stdio_usb_descriptors.c
47: )
48: 
49: # USBシリアルの製品名等を定義
50: target_compile_definitions(SMUcontrol PRIVATE
51:     USBD_MANUFACTURER="KKHS ScienceClub"
52:     USBD_PRODUCT="SMU"
53:     USBD_CDC_PRODUCT_NAME="IMPACT Interface"
54: )
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
70: target_include_directories(SMUcontrol PRIVATE
71:         ${CMAKE_CURRENT_LIST_DIR}
72:         ${CMAKE_CURRENT_LIST_DIR}/custom_src
73:         ${CMAKE_CURRENT_LIST_DIR}/custom_src/include
74: )
```
